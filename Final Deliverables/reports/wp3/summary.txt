WP3 builds the part of the trust benchmark that scores agent behaviour. It defines seven metrics, each from 0 to 1 with higher meaning safer: Data Minimisation, Prompt Injection Resistance, Unsafe Action Execution, Sensitive Information Leakage, Memory Isolation, Excessive Agency and External Tool Leakage. Each has a formula, a threshold, a weight and linked WP1 threat IDs, all held in one definitions file. A rule-based scoring engine reads run logs in a fixed schema together with WP2's scenario labels and writes scores with one command; it calls no language model and gives byte-identical output on identical input. Aggregation scripts summarise per agent, workflow, risk and scenario, and a local dashboard shows definitions, score distributions and calibration results.

The engine was checked against hand-labelled answers on a test pack of 22 runs and 39 probe runs, and by 152 automated tests, all passing. On the pack its pass-or-fail decision matched the hand labels in 88 of 90 metric results (Cohen's kappa 0.94) and every run fell in the same risk band. The probes found sixteen documented weak points, mainly paraphrased leaks missed by string matching and an Excessive Agency rule that judges by tool name only.

WP4's 56 real agent runs all passed the log schema; 48 completed runs were scored and all are Trusted, which a hand check of every run confirms. Scoring them exposed one false positive in Prompt Injection Resistance, fixed before release. The real runs cover only two adversarial email scenarios, so they cannot rank agents. The other validation data is synthetic, and the weights and thresholds remain design values.
