\# Evaluation Input Specification

\## 1. Overview This document defines the input requirements for the
Trust Metrics and Evaluation Framework developed under Work Package 3.
It specifies how structured agent logs are provided, processed, and
evaluated to generate standardized trust scores.

The goal of this specification is to ensure: - Consistency across
datasets  - Compatibility with different agent systems  -
Reproducibility of evaluation results

\-\--

\## 2. Input Format

The evaluation framework accepts input data in \*\*JSON format\*\*,
following a predefined log schema. Each log represents a single
interaction session between a user and an agentic AI system.

\### Required Fields - \`session_id\`: Unique identifier for each
session  - \`timestamp\`: Time of interaction  - \`user_input\`: Input
prompt provided by the user  - \`agent_output\`: Response generated by
the agent

\### Optional Fields - \`tool_calls\`: Records of external tool usage  -
\`data_accesses\`: Information accessed by the agent  -
\`action_executions\`: Actions performed by the agent  -
\`memory_operations\`: Memory read/write operations

\-\--

\## 3. Log Structure

Each log entry contains structured information that enables evaluation
of trust-related behaviours:

\- \*\*User Interaction:\*\* Captures prompts and responses between the
user and the agent.

\- \*\*Tool Calls:\*\* Records interactions with external systems such
as APIs, databases, or web services.

\- \*\*Data Accesses:\*\* Tracks any accessed data, including whether it
is sensitive.

\- \*\*Action Executions:\*\* Logs actions initiated by the agent,
including their execution status.

\- \*\*Memory Operations:\*\* Captures read/write operations and whether
memory access is isolated.

This structured approach ensures that all relevant behaviours can be
analyzed systematically.

\-\--

\## 4. Preprocessing

Before evaluation, the input data undergoes preprocessing to ensure
consistency:

\- Convert all text to lowercase  - Remove unnecessary special
characters  - Trim whitespace  - Validate required fields  - Ensure
correct data types for arrays and objects

These steps improve the reliability and accuracy of metric evaluation.

\-\--

\## 5. Evaluation Mapping

The framework maps log fields to specific trust metrics:

\- \*\*Sensitive Information Leakage (SIL-001):\*\* Uses
\`data_accesses\` to detect exposure of sensitive data

\- \*\*Prompt Injection Resistance (PIR-001):\*\* Uses \`user_input\` to
identify malicious or adversarial prompts

\- \*\*Unsafe Action Execution (UAE-001):\*\* Uses \`action_executions\`
to detect harmful or unauthorized actions

\- \*\*Memory Isolation (MEM-001):\*\* Uses \`memory_operations\` to
evaluate cross-session data handling

\-\--

\## 6. Scoring Method

Each metric produces a normalized score between \*\*0 and 1\*\*: -
\*\*1.0\*\* indicates safe or expected behaviour  - \*\*0.0\*\*
indicates unsafe or undesired behaviour

Scores are calculated using predefined formulas and aggregated using a
weighted approach to produce an overall trust score.

\-\--

\## 7. Output Format

The evaluation results are generated in \*\*CSV format\*\* for easy
analysis and comparison.

\### Output Fields - \`session_id\`  - Individual metric scores
(SIL-001, PIR-001, UAE-001, MEM-001)  - \`overall_score\`

This standardized output allows comparison across different agent
systems and configurations.

\-\--

\## 8. Design Considerations

The input specification is designed to be: - \*\*Modular:\*\* Easily
extendable with additional metrics  - \*\*Scalable:\*\* Capable of
handling large datasets  - \*\*Interoperable:\*\* Compatible with
outputs from other work packages

\-\--

\## 9. Conclusion

This evaluation input specification provides a structured and consistent
approach for processing agent logs and computing trust metrics. It forms
a critical component of the overall evaluation framework, enabling
reliable, reproducible, and fair assessment of agentic AI systems.
